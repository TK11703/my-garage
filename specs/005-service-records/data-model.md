# Data Model: Vehicle Service Records

Two forward-only migrations extend the existing schema (applied by the existing migration runner with the checksum ledger). Applied scripts 0001-0008 are not edited.

## Migration 0009: `0009_create_service_records.sql`

### `service_records`

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key (UUIDv7 generated by the Api). |
| `vehicle_id` | `uuid` | `NOT NULL`, references `vehicles (id)` `ON DELETE CASCADE`. |
| `date_serviced` | `date` | `NOT NULL`, check `>= '1900-01-01'`. |
| `odometer_reading` | `integer` | `NOT NULL`, check `BETWEEN 0 AND 9999999`. |
| `shop_or_person` | `varchar(100)` | `NULL`; free text. |
| `created_at`, `updated_at` | `timestamptz` | `NOT NULL`. |
| `created_by`, `updated_by` | `text` | `NOT NULL`; the authenticated owner id. |

Index: `ix_service_records_vehicle_serviced (vehicle_id, date_serviced DESC, created_at DESC, id DESC)`, serving the list, the count, and the latest-record lookup.

### `service_line_items`

| Column | Type | Rules |
|---|---|---|

| `description` | `varchar(200)` | `NOT NULL`; what service was performed. |
| `flat_cost` | `numeric(12,2)` | `NULL`, check `BETWEEN 0 AND 9999999.99`. |

| `labor_rate` | `numeric(7,2)` | `NULL`, check `BETWEEN 0 AND 99999.99`; hourly rate. |

- `ck_service_line_items_labor_pair`: `(labor_hours IS NULL) = (labor_rate IS NULL)`.

Index: `ix_service_line_items_record (service_record_id, created_at, id)`.

## Migration 0010: `0010_add_vehicle_latest_odometer.sql`

```text
ALTER TABLE vehicles
    ADD COLUMN latest_odometer_reading integer NULL CHECK (latest_odometer_reading BETWEEN 0 AND 9999999);
```

The existing `mileage` column (mileage on the purchase or lease date) is unchanged.

## Relationships and lifecycle

```text
users (Entra id) 1 --- * vehicles 1 --- * service_records 1 --- * service_line_items 1 --- * service_line_item_parts
```

- A service record belongs to one vehicle; a line item to one record; a part to one line item.
- Deleting a vehicle, a record, or a line item cascades to everything beneath it.
- Ownership is never stored on service tables; every statement proves it through `vehicles.owner_id` (research R2).

## Derived values

| Value | Definition |
|---|---|
| Line item total | Flat cost; or `round(labor_hours x labor_rate, 2) + sum(round(quantity x unit_price, 2))` over its parts (`MidpointRounding.AwayFromZero`). |
| Service record total cost | `SUM(service_line_items.total_cost)` for the record; 0.00 with no line items. |
| Effective mileage (garage card and mileage filters) | `GREATEST(odometer_reading of the latest-dated record, vehicles.latest_odometer_reading, vehicles.mileage)`; null only when all three are null. |
| Service history summary | Record count; most recent `date_serviced`. |

## State and transitions

No status machine. A record may exist with no line items (total 0.00). A line item's pricing mode is implied by its data: flat cost set (breakdown empty) or labor/parts set (flat cost null). Editing a line item switches modes by replacing all of its pricing fields and parts together.

## Validation summary (enforced by FluentValidation; database checks are a backstop)

| Field | Rule |
|---|---|
| Date Serviced | Required; not in the future (UTC date); not before 1900-01-01. |
| Odometer Reading | Required; whole number 0-9,999,999. |
| Shop Name or Person | Optional; trimmed; 1-100 characters; no control characters; blank means not set. |
| Line description | Required; trimmed; 1-200 characters; no control characters. |
| Flat cost | 0.00-9,999,999.99; at most 2 decimals; cannot be combined with labor or parts. |
| Labor | Hours (0.01-999.99, at most 2 decimals) and hourly rate (0.00-99,999.99, at most 2 decimals) are required together. |
| Parts | At most 25; each: name required 1-100 characters; quantity 0.01-9,999.99 (at most 2 decimals); unit price 0.00-9,999,999.99 (at most 2 decimals). |
| Line item pricing | One of flat cost, or labor and/or at least one part. Computed total must not exceed 9,999,999.99. |
| Line items per record | At most 50 (409 beyond). |
| Latest Odometer Reading (vehicle) | Optional; whole number 0-9,999,999. |

## Persistence types (internal to `MyGarage.Database`, never exposed)

`ServiceRecordRecord` (id, date serviced, odometer, shop or person, audit columns, line item count, total cost), `ServiceLineItemRecord`, `ServiceLinePartRecord`, `ServiceRecordDetailRecord` (record plus its line items and parts), and `ServiceCostCalculator`. `VehicleRecord` gains `LatestOdometerReading`; `VehicleSummaryRecord.Mileage` becomes the effective mileage.
