- **[Story]**: US1-US8, only on user-story phase tasks
- Constraints from data-model.md and research.md are quoted in the task that creates the artifact; do not loosen them
- This feature adds no projects, packages, or Aspire resources (research R16)
- Every new SQL statement proves ownership with `JOIN vehicles v ON v.id = <table>.vehicle_id WHERE v.owner_id = @OwnerId` plus the route's `@VehicleId` (and the entry id when addressing one entry); no new table has an `owner_id` column (research R2)
- Names used for each kind (keep them identical in every layer): **fuel/charging** = `FuelEnergyEntries` / `FuelEnergyEntry` / table `fuel_energy_entries` / route `fuel-energy-entries`; **inspection** = `Inspections` / `Inspection` / `inspections` / `inspections`; **registration** = `Registrations` / `Registration` / `registrations` / `registrations`; **insurance** = `Insurance` / `InsurancePolicy` / `insurance_policies` / `insurance`; **tax** = `Taxes` / `Tax` / `taxes` / `taxes`
- Enumerations travel as PascalCase names in JSON and are stored as lowercase text (`fuel`, `energy`, `safety`, `emissions`, `personal_property`, `lease`, `purchase`, `once`, `monthly`, `bi_annual`, `annual`); the explicit conversion lives in each Api mapper (research R4)
- Repository method shape for every kind (all async, last parameter `CancellationToken cancellationToken`): `AddAsync(string ownerId, Guid vehicleId, Guid id, <values>, DateTimeOffset now)` -> record or null; `ListPageAsync(string ownerId, Guid vehicleId, int page, int pageSize)` -> `PagedResult<TRecord>?` (null when the vehicle is not the owner's); `GetAsync(string ownerId, Guid vehicleId, Guid id)` -> record or null; `UpdateAsync(string ownerId, Guid vehicleId, Guid id, <values>, DateTimeOffset now)` -> record or null; `DeleteAsync(string ownerId, Guid vehicleId, Guid id)` -> bool
- Endpoint shape for every kind: `MapGroup("/api/vehicles/{vehicleId:guid}/<route>").WithTags("<Kind>")` with `GET ""` (page size default 10, clamped to the last page like `ServiceRecordsEndpoints`), `POST ""` (201 + `Location`), `GET "/{entryId:guid}"`, `PUT "/{entryId:guid}"`, `DELETE "/{entryId:guid}"` (204); owner from `CurrentOwner.Get(user)` with `VehiclesEndpoints.NoOwner()` / `NotFound()`; `ValidationFilter<TRequest>` on create and update; `Produces`/`ProducesProblem` for 200/201/204/400/401/403/404; ids from `Guid.CreateVersion7()`; time from `TimeProvider`
- Web page shape for every kind: static SSR (`[Authorize]`, `[ExcludeFromInteractiveRouting]`, `[SupplyParameterFromForm(FormName = ...)]`, post-redirect-get), `PageHeader` trail Vehicles > vehicle name > page title, 404 shows `EmptyState` with a 404 status and a link back to the Maintenance tab, `ApiFailureAlert` for failures, the same structure as `src/MyGarage.Web/ServiceRecords/ServiceRecordCreate.razor` and `ServiceRecordEdit.razor`

## Dependencies & Execution Order

### Phase dependencies

- **Setup (Phase 1)**: no dependencies
- **Foundational (Phase 2)**: depends on Setup; **blocks every user story**
- **US1 (Phase 3)**: depends on Foundational only; it is the MVP
- **US2, US3, US8, US4 (Phases 4-7)**: each depends on Foundational only (US2 also creates `ComplianceSection.razor`, so US3, US8, and US4 depend on T037 for the Web wiring tasks T049, T060, and T071; their database and API tasks do not)
- **US5 (Phase 8)**: each kind's tasks depend on that kind's phase; the fuel and charging parts (T075, the fuel half of T080, T081, T082) can run right after US1
- **US6 (Phase 9)**: guard tests per kind can be written as soon as that kind's API exists; T088 is last
- **US7 (Phase 10)**: depends on US1 and US2 at minimum (headings), complete after US3, US8, and US4
- **Polish (Phase 11)**: depends on all desired stories

### Within each story

- Tests are written and confirmed failing before implementation
- DTOs and migration before repositories; repositories before endpoints; endpoints before the Web client; client before pages
- Each story's checkpoint is met before moving on

### Parallel opportunities

- Foundational tests T002-T007 together; T008, T010, T011, T013, T014, T015 together after their tests; T009 touches existing files and should not run alongside other edits to `src/MyGarage.Api/ServiceRecords/`
- Within a kind: its four test tasks together; DTOs and validators together; the Web client task together with the endpoint task
- **The four P2 kind phases (US2, US3, US8, US4) touch different feature folders and can be done in parallel by different developers**; the only shared files are `src/MyGarage.Api/Program.cs`, `src/MyGarage.Web/Program.cs`, `DatabaseServiceCollectionExtensions.cs`, and `ComplianceSection.razor`, so merge those edits carefully
- US5 per-kind tasks T076-T079 and the per-kind edit pages in T083 are independent of each other
