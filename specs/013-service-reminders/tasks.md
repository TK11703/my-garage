# Tasks: Service Reminders

**Input**: Design documents from `/specs/013-service-reminders/`

**Prerequisites**: plan.md, spec.md (with the 2026-11-06 planning refinement), research.md (D1-D15), data-model.md, contracts/api.openapi.yaml, contracts/web-routes.md, quickstart.md

**Tests**: Required (constitution VIII): write the test, run it, watch it fail for the right reason, then implement. The database is never mocked (Testcontainers PostgreSQL). There is no external AI or blob dependency in this feature, so nothing is faked except `TimeProvider` (use `FakeTimeProvider` or the test clock already used by the draft expiry tests) and the Api behind the Web (fake `HttpMessageHandler` or the existing `VehicleTestContext` responders).

**Organization**: Grouped by user story. US1 set up a reminder and see it on the vehicle (P1, smallest slice); US2 status and the garage-wide list (P1); US3 mark done and roll forward (P1); US4 notifications (P2); US5 edit, pause, delete (P2); US6 dashboard (P2). The Foundational phase holds the shared contracts, the migration, and the status calculator that every story reads. Status is computed on read (research D1), so US1 already returns it in the DTO; US2 adds the urgency order, badges, and the garage list.
