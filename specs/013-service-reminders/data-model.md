# Data Model: Service Reminders

Forward-only migration `0016_create_reminders.sql`. Dates are `date`, instants are `timestamptz`, and every table follows the audit columns of the maintenance tables (`created_at`, `updated_at`, `created_by`, `updated_by`).

## Entities

### Reminder (`reminders`)

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` PK | Version 7, generated by the Api. |
| `vehicle_id` | `uuid` NOT NULL | FK `vehicles (id)` ON DELETE CASCADE. Ownership is the vehicle's `owner_id`; the table has no owner column. |
| `name` | `varchar(100)` NOT NULL | Trimmed, not blank. |
| `applies_to` | `varchar(9)` NOT NULL | CHECK in `vehicle`, `equipment`, `location`. |
| `subject` | `varchar(100)` NULL | CHECK: NULL when `applies_to = 'vehicle'`, not blank otherwise. |
| `interval_miles` | `integer` NULL | CHECK between 1 and 999999. |
| `interval_months` | `integer` NULL | CHECK between 1 and 600 (years 1 to 50 convert to 12 to 600). |
| `last_done_on` | `date` NOT NULL | CHECK `>= DATE '1900-01-01'`; the Api refuses a future date. |
| `last_done_mileage` | `integer` NULL | CHECK between 0 and 9999999; NOT NULL when `interval_miles` is set (table CHECK). |
| `is_paused` | `boolean` NOT NULL | Default false. |
| `notified_state` | `varchar(8)` NULL | CHECK in `due_soon`, `overdue`; the last state the owner was told about. |
| `created_at`, `updated_at` | `timestamptz` NOT NULL | |
| `created_by`, `updated_by` | `text` NOT NULL | The authenticated owner id. |

Table CHECK: at least one of `interval_miles` and `interval_months` is NOT NULL.

Indexes: `ix_reminders_vehicle (vehicle_id, created_at, id)`.

**Derived, never stored**: next due mileage, next due date, status, miles remaining, days remaining (computed by `ReminderStatusCalculator`).

### Reminder completion (`reminder_completions`)

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` PK | |
| `reminder_id` | `uuid` NOT NULL | FK `reminders (id)` ON DELETE CASCADE. |
| `done_on` | `date` NOT NULL | Not in the future (Api), `>= DATE '1900-01-01'`. |
| `mileage` | `integer` NULL | CHECK between 0 and 9999999. |
| `created_at` | `timestamptz` NOT NULL | |
| `created_by` | `text` NOT NULL | |

Index: `ix_reminder_completions_reminder (reminder_id, done_on DESC, created_at DESC, id DESC)`.

### Notification (`notifications`, changed)

| Change | Detail |
|---|---|
| `kind` check | Drop `notifications_kind_check`; add a check for `draft_ready`, `reminder_due_soon`, `reminder_overdue`. |
| `reminder_id uuid NULL` | FK `reminders (id)` ON DELETE CASCADE. |
| Shape check | `(kind = 'draft_ready' AND draft_id IS NOT NULL AND reminder_id IS NULL) OR (kind <> 'draft_ready' AND reminder_id IS NOT NULL AND draft_id IS NULL)`. |
| Index | `ix_notifications_reminder (reminder_id) WHERE reminder_id IS NOT NULL`. |

Existing rows are all `draft_ready` with a draft, so the shape check holds for them.

### Existing entities used

- **Vehicle**: owner of reminders; supplies the current mileage and `latest_odometer_reading` (raised on request when a reminder is marked done).
- **Service record**: its odometer feeds the current mileage; reminders never reference it.

## Relationships

```text
vehicles 1 ─── * reminders 1 ─── * reminder_completions
                    │
                    └── 0..* notifications (reminder_id, cascade)
```

Deleting a vehicle removes its reminders, their completions, and their notifications by cascade (FR-018).

## Validation rules (Api, FluentValidation)

**ReminderRequest**
- `name`: required, trimmed, 1 to 100 characters.
- `appliesTo`: one of `vehicle`, `equipment`, `location`.
- `subject`: required (1 to 100 characters) for `equipment` and `location`; must be empty for `vehicle`.
- `intervalMiles`: null or a whole number 1 to 999999.
- `intervalTime`: null, or `value` and `unit`; unit `months` (1 to 600) or `years` (1 to 50); whole numbers.
- At least one of the two intervals is present.
- `lastDoneOn`: required, not in the future, not before 1900-01-01.
- `lastDoneMileage`: whole number 0 to 9999999; required when `intervalMiles` is present.
- Defaults (today, the vehicle's current mileage) are supplied by the Web form, not by the server.

**CompleteReminderRequest**
- `doneOn`: required, not in the future, not before 1900-01-01.
- `mileage`: whole number 0 to 9999999; required when the reminder has a distance interval; not below the reminder's current `last_done_mileage` (checked in the endpoint after loading the reminder).
- `updateVehicleMileage`: boolean; honored only when `mileage` is above the vehicle's current mileage.

## State rules

Status is computed (see [research.md](research.md) D2):

```text
paused                                  -> Paused
distance-only and no current mileage    -> Mileage needed
any due point reached or passed         -> Overdue
within 500 miles or 30 days of a point  -> Due soon
otherwise                               -> Upcoming
```

`notified_state` transitions (D9), evaluated by `ReminderEvaluator`:

| Computed state | `notified_state` before | Action |
|---|---|---|
| Due soon | NULL | Insert `reminder_due_soon` notification; set `due_soon`. |
| Overdue | NULL or `due_soon` | Insert `reminder_overdue` notification; set `overdue`. |
| Due soon | `overdue` | No notification; set `due_soon`. |
| Upcoming, Paused, Mileage needed | any | No notification; set NULL (and mark the reminder's notifications read when moving to Paused or Upcoming from marking done or editing). |
| Same as before | same | Nothing. |

Marking done sets `last_done_*`, inserts a completion, and sets `notified_state` NULL in one transaction. Editing recalculates and re-evaluates. Pausing sets `is_paused` and marks notifications read; resuming re-evaluates.

## Dashboard read model

`DashboardDto` has no table. `Dashboard/Counts.sql` returns one row of owner-scoped counts: vehicles, service records (through the owner's vehicles), fuel and charging entries (through the owner's vehicles), and drafts awaiting review (the same rule as `Notifications/CountDraftsAwaitingReview.sql`). Reminder counts and the attention list come from `ReminderRepository.ListForOwnerAsync` plus the calculator.
