# Tasks: Window Sticker Upload Shortcut

**Input**: Design documents from `/specs/010-window-sticker-upload/`

**Prerequisites**: plan.md, spec.md (with Amendment 1), research.md (R1-R11), data-model.md, contracts/api.openapi.yaml, contracts/web-routes.md, quickstart.md

**Tests**: Required (constitution VIII): write the test, run it, watch it fail for the right reason, then implement. The database is never mocked; only the AI boundary is faked (a fake `IStickerExtractor` for endpoint tests, a fake `HttpMessageHandler` for the extractor client).

**Organization**: Grouped by user story. US1 import fills the form on add and edit, with proposed features and consolidation (P1); US2 clear failures and notices (P1); US3 privacy, rate limit, and logging (P2). The Foundational phase holds the shared DTOs, the transport refactor, the feature key, and the database write that every story reads, so the stories can then be done in order.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: US1-US3, only on user-story phase tasks
- Names to keep identical everywhere: tab id `import` (label "Import from sticker"); named form `import-sticker`; file field `stickerFile`; endpoint `POST /api/vehicles/sticker-extractions`; DTOs `StickerImportResultDto`, `StickerFeatureDto`, `StickerNoticeDto`, `StickerImportOutcome`, `StickerImportLimits`; request types `StickerFeatureRequest` and `VehicleRequest.StickerFeatures`; settings section `StickerImport` (`TimeoutSeconds`, default 45); rate-limit policy `sticker-import`; meter `MyGarage.StickerImport`; form model rows `StickerFeatureChoice`
- No new NuGet package; no new project; no migration; no new table or storage container
- Never run `dotnet test` while `aspire run` is active
- Work on branch `010-window-sticker-upload`; never commit to `main`; merge by pull request
