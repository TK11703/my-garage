# My Garage UI Standard

How every page in `MyGarage.Web` looks and behaves. New pages follow this document; the automated test `UiStandardConformanceTests` guards the parts that can be checked in source. Bootstrap 5.3.x is the only UI framework.

## Logo

| Asset | File | Use |
|---|---|---|
| Mark on dark | `src/MyGarage.Web/wwwroot/images/logo-mark-on-dark.svg` | Dark surfaces (the rail and public bar draw an "MG" tile in CSS instead) |
| Mark on light | `src/MyGarage.Web/wwwroot/images/logo-mark-on-light.svg` | Light surfaces, documents |
| Favicon | `src/MyGarage.Web/wwwroot/images/favicon.svg` | Browser tab; self-contained tile that reads at 16 px |

- The name "My Garage" is always real text next to the mark (never part of the image). The mark image has `alt=""` because the adjacent text names the link.
- Minimum size: 24 px for the mark, 16 px for the favicon.
- Clear space: at least a quarter of the mark's height on every side.
- Do not stretch, rotate, recolor, add effects, or place the dark-background mark on a light surface.

## Palette and themes

My Garage is one design ("instrument cluster") in two palettes, light and dark. Layout, type, spacing, radius, and motion are shared; dark mode swaps color values only. The full token list, with measured contrast, is in [design-tokens.md](design-tokens.md), and [design-tokens-preview.html](design-tokens-preview.html) shows every token live in both themes. The page-by-page reference visuals are in [mockups/](mockups/) (open `b-garage.html` first).

Every color is a CSS variable in `wwwroot/css/tokens.css`, defined once for light (`:root`) and once for dark (`[data-bs-theme="dark"]`); the same file maps them onto Bootstrap's variables so stock Bootstrap components follow the design. Never hard-code a color in a component or in `app.css`; use a `--mg-*` token or a Bootstrap utility so both themes work (`DesignTokenTests` fails on a hex literal in `app.css`).

| Token | Light | Dark | Use |
|---|---|---|---|
| `--mg-bg` | `#E6EBEF` | `#080B0E` | Page background |
| `--mg-surface` / `--mg-surface-2` | `#FFFFFF` / `#F1F4F7` | `#10151A` / `#171E25` | Cards and panels / inputs and inset blocks |
| `--mg-line` / `--mg-line-strong` | `#D2DAE1` / `#7E8B98` | `#222B34` / `#5F6E7C` | Dividers and card edges / control edges (3:1) |
| `--mg-text` / `--mg-text-muted` | `#0E1318` / `#5A6672` | `#E8EEF3` / `#8895A2` | Text |
| `--mg-accent` / `--mg-accent-text` | `#BC7000` / `#8F5400` | `#FFB000` | Amber fills and rings / amber links and small text |
| `--mg-ok`, `--mg-due`, `--mg-bad` | `#187A43`, amber, `#C23B30` | `#3DDC84`, amber, `#FF5B4D` | Status only: upcoming, due soon, overdue |
| `--mg-rail-*` | dark in both | darker | The navigation rail |
| `--mg-paper-*` | paper in both | paper in both | Window sticker and invoice documents |

Status vocabulary: red is overdue or failed, amber is due soon, green is upcoming or ready, a muted dashed treatment means mileage is needed, and a dimmed treatment means paused or archived. Never use a status color for decoration.

Type: Chakra Petch (display, uppercase titles and numerals), Inter (body), JetBrains Mono (labels, codes, and figures). All three are self-hosted WOFF2 files in `wwwroot/fonts/` with their OFL licences, loaded by `wwwroot/css/fonts.css`; nothing is fetched from a font host.

### Choosing the theme

Light and Dark only (there is no System option in the UI). The sun/moon button in the rail (and in the public bar) switches theme. The choice is kept only in the browser (`localStorage` key `mg-theme`, never sent to the server or saved in the database), so a new browser or a private window starts from the system setting (`prefers-color-scheme`). `wwwroot/js/theme-init.js` runs in the head so the page never flashes the wrong theme; `wwwroot/js/app-shell.js` handles the toggle and the phone drawer. Both are classic scripts.

Theming is done by overriding Bootstrap 5.3 CSS custom properties in `wwwroot/css/tokens.css`; there is no Sass build.

## Typography and spacing

- Page title: the only `h1`, rendered by `PageHeader` in the display face, uppercase. Sections use `h2` with `h5` styling; sub-sections use `h3`.
- Body text is Inter; secondary text uses `text-body-secondary`; small print uses `small`; figures that line up (odometer, money, codes) use the `mg-num` class.
- Content gutters come from the content area (`mg-content`); the page bar has space below it. Use `gap-2` between buttons and `gap-3` between blocks. Readable-width pages (forms, FAQ, About) constrain themselves with `col-lg-8`.

## Page frame

1. Skip link ("Skip to main content") is the first focusable element.
2. Signed in: `AppRail`, a fixed 68 px dark rail on the left, with the logo tile, then Garage (`GAR`), Add vehicle (`NEW`), Reminders (`REM`), Drafts (`DRF`, with the awaiting-review count), Search (`SRC`), and Dashboard (`DSH`); at the bottom Notifications, Help (FAQ and About), the theme toggle, and the account (initials) with Preferences and Sign out. Each item draws a three-letter code and is named in full for assistive technology (`visually-hidden` text and a `title`); the current item is highlighted and carries `aria-current="page"`. Under 768 px the rail is hidden and a slim top strip with a menu button opens it as a drawer (Escape or the backdrop closes it, and choosing an item closes it).
3. Signed out and public pages (FAQ, About, signed out, sign-in problem): `PublicBar`, a dark top bar with the logo, FAQ and About links, the theme toggle, and Sign in. The rail never shows for signed-out visitors.
4. `<main id="main-content" class="mg-content">` (with `mg-content-with-rail` beside the rail, or `mg-content-public` under the public bar). Its first child is always `PageHeader`. Put cards and other content in surfaces (`card`) on the page background.

Search is its own page, `GET /search?q=` (the owner-scoped vehicle search). Notifications is a menu that opens to the right of the rail, with a small amber dot on the bell when anything is unread (no count on the bell; the button is named "Notifications, N unread"; the bell shakes briefly every 5 seconds while anything is unread, except with reduced motion). The menu has a header with an "N new" pill, a list of the latest 20 notifications that scrolls when long (icon tile, title, time since, and a dot when unread; one that has a draft links to it; an × button dismisses it), and a footer with "Mark all as read" (while any is unread) and "Clear read" (while any is read). Help links to `/faq` and `/about`, which are viewable without signing in. The account menu shows the user's own name and email, Preferences, and Sign out (antiforgery `POST /authentication/logout`).

## Page header: title, trail, and actions

`<PageHeader Title="..." Trail="@(new[] { new Crumb("Vehicles") })">` renders the page bar: a small mono location line above a large uppercase display title at the left (the title stays first in the document for assistive technology; CSS shows the location line above it), and any page actions at the right (buttons, or controls that open a filter or search). The breadcrumb is "Home", then the name of the area the page sits under (Garage, Maintenance, or Help), then the trail **without its last crumb**, because the last crumb is the current page and the title already names it. The trail's first crumb is that area's own page (for example Vehicles under Garage), so the area name stands for it: it is a link when that crumb has an address and plain text when it does not, and the crumb is not repeated. Pages outside those areas (Preferences, sign-in pages, the home page) show no group, and a page with no breadcrumb parts shows none. The page therefore still passes its full trail, as listed below. Page actions render as normal buttons, with at most one primary (amber). The title scales from 1.5 rem on a phone up to the large display size. The title also sets the browser tab title to "{Title} – My Garage".

| Page | Route | Trail (after Home) | Title |
|---|---|---|---|

|---|---|

| Destructive action | `btn btn-outline-danger` to open, `btn btn-danger` to confirm (Destructive: soft red; muted dark red in the dark theme) |
| Quiet actions | Ghost (a plain `btn`) and `btn btn-link` (blue text). Page-bar actions render as ghost text links whatever their class. Buttons have 8 px rounded corners; the sample set is on the preview page |
| Form buttons | Submit first, then Cancel. The Save button carries `data-busy-text="Saving..."`, so once submitted it shows a spinner and the text and stays disabled (`submit-busy.js`) |
| Row-level buttons | `btn-sm`; page-level buttons regular size |
| Destructive confirmation | Inline `<details>` with a danger alert, a POST form, and buttons "Yes, delete this {vehicle, note, picture}" and "Keep {vehicle, note, picture}". Feature removal is immediately reversible, so it is a one-click remove button with the accessible name "Remove feature {name}" |
| Forms | Bootstrap floating labels (`form-floating`, input before label) on every field; the search boxes keep a visible label and hint. Read-only views use the same grid as the edit form with a small label stacked over each value (`ViewField`), not label/value rows; required fields marked with a visible `*` (`aria-hidden`) and a "* Required" note as the first thing in the form's first card body (never beside the buttons); field errors use `invalid-feedback d-block`; forms limited to `col-lg-8` |

| View page | Page header with an Add menu, Edit, Archive or Restore, and Delete (each with its confirmation). ## Accessibility

- Every interactive element is keyboard operable with a visible focus indicator (a white outline on the dark rail and bars, an amber-text outline elsewhere).
- Icon-only controls carry an accessible name (`aria-label`); icons are `aria-hidden`.
- Motion is disabled for users who prefer reduced motion.
- Pages work from 320 px to 1920 px without horizontal scrolling of primary content.

## Icons

Icons are inline SVGs rendered by `Common/Icon.razor`. The glyph paths come from [Bootstrap Icons](https://icons.getbootstrap.com/) (MIT license, Copyright (c) 2019-2024 The Bootstrap Authors).


## Cleanup rules

- `app.css` holds component CSS and the Bootstrap bridge only. Colours come from `tokens.css` (`--mg-*`); a test fails on any hex literal in `app.css` and on any of the pre-redesign token names (`--mg-primary`, `--mg-card-radius`, `--mg-night`, and so on). Chart series colours (`--mg-chart-1` to `--mg-chart-7`, `--mg-chart-other`) live in `tokens.css`.
- Bootstrap's own status colours are bridged to the tokens (`--bs-success-rgb`, `--bs-danger-rgb`, `--bs-warning-rgb`, `--bs-info-rgb`), so `text-success`, `text-bg-danger`, and the like show the token colours in both themes. Neutral information such as search chips uses `mg-chip`, not a status colour. Mileage needed is a muted status.
- The home page photo and its hero styles are gone; the garage page is the home page.
