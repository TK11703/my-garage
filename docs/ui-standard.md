# My Garage UI Standard

How every page in `MyGarage.Web` looks and behaves. New pages follow this document; the automated test `UiStandardConformanceTests` guards the parts that can be checked in source. Bootstrap 5.3.x is the only UI framework.

## Logo

| Asset | File | Use |
|---|---|---|
| Mark on dark | `src/MyGarage.Web/wwwroot/images/logo-mark-on-dark.svg` | Navigation bar (blue background) |
| Mark on light | `src/MyGarage.Web/wwwroot/images/logo-mark-on-light.svg` | Light surfaces, documents |
| Favicon | `src/MyGarage.Web/wwwroot/images/favicon.svg` | Browser tab; self-contained tile that reads at 16 px |

- The name "My Garage" is always real text next to the mark (never part of the image). The mark image has `alt=""` because the adjacent text names the link.
- Minimum size: 24 px for the mark, 16 px for the favicon.
- Clear space: at least a quarter of the mark's height on every side.
- Do not stretch, rotate, recolor, add effects, or place the dark-background mark on a light surface.

## Palette and themes

The application has a light and a dark theme. Open [theme-preview.html](theme-preview.html) in a browser to see both themes, the page frame, every shared component, and all color swatches; it loads the application's own `app.css`, so it always matches the real look.

Every color is a CSS variable in `wwwroot/app.css`, defined once for light (`:root`) and once for dark (`[data-bs-theme="dark"]`). Never hard-code a color in a component; use a variable or a Bootstrap utility so both themes work.

Contrast ratios (WCAG relative luminance): white on the light top bar 4.60:1; white on the light primary 5.75:1; white on the dark primary 4.60:1; menu text on the left menu above 9:1 and its muted group labels above 5:1. All meet AA (4.5:1 for text, 3:1 for UI components).

### Choosing the theme

The sun/moon button at the right end of the top bar switches theme. The choice is kept only in the browser (`localStorage` key `mg-theme`, never sent to the server or saved in the database), so a new browser or a private window starts from the system setting (`prefers-color-scheme`). `wwwroot/js/theme-init.js` runs in the head so the page never flashes the wrong theme; `wwwroot/js/app-shell.js` handles the toggle. Both are classic scripts so the preview page can load them from disk.

Theming is done by overriding Bootstrap 5.3 CSS custom properties in `wwwroot/app.css`; there is no Sass build.

## Typography and spacing

- Page title: the only `h1` (`h2` styling), rendered by `PageHeader`. Sections use `h2` with `h5` styling; sub-sections use `h3`.
- Body text is Bootstrap's default; secondary text uses `text-body-secondary`; small print uses `small`.
- Content gutters come from the content area (`mg-content`, 1rem on a phone and 1.5rem from tablet up); the page bar sits flush at its top and has `mb-3` space below it. Use `gap-2` between buttons and `gap-3` between blocks. Readable-width pages (forms, FAQ, About) constrain themselves with `col-lg-8`.

## Page frame

1. Skip link ("Skip to main content") is the first focusable element.
2. `AppNavbar`: a fixed, full-width blue bar. Signed in: hamburger button (phone only), logo and name, search, notifications bell, and the theme toggle at the far right. Signed out: logo and name, help (FAQ, About), the theme toggle, and Sign in.
3. `AppSidebar` (signed in only): a fixed dark-grey vertical menu under the top bar. It starts with the profile (avatar, name, and email, with a dropdown holding Preferences and Sign out), then grouped items. Group headings are small, uppercase, and muted, with no icon; every item has an icon and normal-size text; the current page is highlighted and carries `aria-current="page"`. Home sits on its own above the groups, then the groups: Garage (My Vehicles, Add Vehicle), Maintenance (Maintenance Drafts with the awaiting-review count, Add Maintenance), Help (FAQ, About). From 1200 px up the menu is 16.5 rem wide; from 768 px to 1199 px it is a rail of icons (names stay as tooltips and for screen readers); under 768 px it is hidden and the hamburger button slides it over the page (Escape or the backdrop closes it).
4. `<main id="main-content" class="mg-content">` (with `mg-content-with-sidebar` when the menu is shown) on the grey content background. It scrolls under the top bar and to the right of the menu. Its first child is always `PageHeader`, the page bar, pinned to the top of the content while the rest scrolls. Put cards and other content in white surfaces (`card`) on top of the grey.

The search box submits `GET /search?q=` (the owner-scoped vehicle search page). Notifications is a menu with a small yellow dot under the bell when anything is unread (no count; the button is named "Notifications, N unread"), the latest five notifications, "Mark all as read", and a link to the drafts; the dot is hidden at zero. Help links to `/faq` and `/about`, which are viewable without signing in. The account menu shows the user's own name and email, Preferences, and Sign out (antiforgery `POST /authentication/logout`).

## Page header: title, trail, and actions

`<PageHeader Title="..." Trail="@(new[] { new Crumb("Vehicles") })">` renders the page bar: the title at the left, followed by the breadcrumb, and any page actions at the right (buttons, or controls that open a filter or search). The breadcrumb is "Home", then the name of the menu group the page sits under (Garage, Maintenance, or Help; plain text), then the trail **without its last crumb**, because the last crumb is the current page and the title already names it. Pages outside the menu groups (Preferences, sign-in pages, the home page) show no group, and a page with no breadcrumb parts shows none. The page therefore still passes its full trail, as listed below. Page actions render as text links (no filled buttons); a destructive confirmation panel inside them keeps real buttons. The title is small (0.9375 rem) and semibold. The page bar uses the same background as the left menu so the two read as one connected piece, with light text, light breadcrumb links, and light page-action links in both themes. The title also sets the browser tab title to "{Title} – My Garage".

## Accessibility

- Every interactive element is keyboard operable with a visible focus indicator (white outline on the blue bar and the dark menu).
- Icon-only controls carry an accessible name (`aria-label`); icons are `aria-hidden`.
- Motion is disabled for users who prefer reduced motion.
- Pages work from 320 px to 1920 px without horizontal scrolling of primary content.
